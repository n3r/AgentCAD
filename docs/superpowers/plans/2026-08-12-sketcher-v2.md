# Sketcher v2 — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: use
> `superpowers:subagent-driven-development` (recommended) or
> `superpowers:executing-plans` to work through this plan slice by slice.
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** ship [PRD-009](../../prd/in-progress/PRD-009-sketcher-v2.md) — arcs,
splines, ellipses and slots in the constraint solver *and* the GUI sketcher;
generalized tangency, symmetry, equality and concentricity; a real `initial`
warm start; rank-based DOF diagnostics with a named conflicting set;
drag-to-solve at interactive rate without mirror flips; sketch-on-face with
projected references; and one shared server-side emitter producing idiomatic
build123d that rebuilds to the solved coordinates — per
[the design spec](../specs/2026-08-12-sketcher-v2-design.md).

**Architecture (one paragraph):** `agentcad/toolkit/sketch.py` is rebuilt
around a typed residual IR — every constraint compiles to `Residual` records
carrying `con_index`, the parameter slots it touches, its value function and
its **analytic derivative** — which buys three things at once: a Jacobian that
costs one pass instead of `n_par + 1` (measured 66× at the FR6 size), a rank
analysis that can name the constraint a user wrote, and a `PointRef`
indirection under which arcs, ellipses, splines and slots reuse the existing
constraint vocabulary instead of multiplying it. Diagnostics are a pure-numpy
post-pass (SVD for rank/DOF/free entities; **declaration-order greedy** forward
selection for the dependent set — column-pivoted QR was measured to blame the
wrong constraint). Drag runs **on the server over keep-alive HTTP**, seeded
from the previous frame with the cursor entering as a *weighted soft objective*
that is excluded from every reported quantity. A new
`agentcad/core/sketch_emit.py` is the single emitter for both the GUI and
agents, emitting endpoint-anchored curves at 9 decimals behind a measured
closure gate. Sketch-on-face adds one worker handler pack
(`kernel/handlers/sketchplane.py`) for the plane basis and projected
references. Surfaces stay packs: `core/tools_sketch.py`,
`server/routes_sketch.py`, `frontend/js/sketcher.js`.

**Tech stack:** Python 3.12 + numpy 2.5.1 + scipy 1.18.0 (both **promoted from
transitive to declared** in slice 1 — they arrive today only because build123d
requires scipy, and the server may not import build123d) / FastAPI route pack /
pytest with the session-scoped `kernel` fixture / plain ES modules and SVG in
`frontend/js/sketcher.js`. **No new runtime dependency. No new vendored
frontend library. No WASM.** The rejected alternatives and why are Decision 1
of the design spec.

  `agentcad/toolkit/sketch.py` runs in the **server** process (it is imported
  by `core/tools_sketch.py`) and must stay OCP-free — it is one of exactly two
  toolkit modules with that property (`specs.py` is the other; `facemod`,
  `fillet`, `shell`, `surfacing`, `sheetmetal`, `threads` all import `b3d` and

  7. `agentcad/core/templates.py` (CHEATSHEET), `pyproject.toml` (deps),

## Slice 2 — the residual IR and analytic Jacobians

The rewrite that buys every interactive target. **Zero behaviour change**: the
v1 corpus from slice 1 is the gate.

### Files
- `agentcad/toolkit/sketch.py`
- `tests/test_sketch_jacobian.py` — **new**
- `tests/test_sketch_bench.py`
- `docs/changelog/NNNN-sketch-analytic-jacobian.md`

### Tasks
- [ ] Introduce `Residual` (frozen dataclass, `slots=True`) with `con_index`,
      `kind`, `rows`, `params: tuple[int, ...]`, `f(v) -> np.ndarray`,
      `df(v, J, row0) -> None`. Design spec Decision 2 has the shape.
- [ ] Introduce `PointRef`: resolve a name to `(value_fn, grad_fn, params)`.
      For a free point that is `(v[ix], v[ix+1])` and two unit gradient rows;
      for a fixed point it is a constant with **empty** `params`. Rewrite every
      v1 constraint against `PointRef` — this is what makes slice 5's virtual
      arc handles free.
- [ ] Give every v1 residual an analytic `df`. All 17 are elementary:
      polynomials, `hypot`, normalized cross/dot products, `atan2`. Derive them
      on paper, then let the test below prove them.
- [ ] Assemble the Jacobian into a **dense** preallocated `np.ndarray` by index
      assignment. Do not reach for `scipy.sparse` — measured unnecessary
      through 400 parameters (design Decision 1), and it would cost the SVD
      path the diagnostics need.
- [ ] Pass `jac=` to `least_squares` and switch to `method="trf"` uniformly
      (MINPACK's `lm` requires `m >= n`, which an under-constrained sketch
      violates; the measurement shows the method is noise next to the Jacobian).
- [ ] Keep `solve_sketch(spec) -> dict` and every v1 result key byte-compatible.
      `parse` and `solve` split so slices 3, 4 and 8 have somewhere to hook.
- [ ] Turn on the FR6 assertions in `tests/test_sketch_bench.py`: warm-drag
      **p50 ≤ 16 ms** and cold **p50 ≤ 250 ms** at `n_seg = 50`, with a
      documented 3× headroom note and the measured value printed on failure.

### Tests (`tests/test_sketch_jacobian.py`)
- [ ] **The central test of this plan:** for every registered residual kind,
      build a small sketch containing it, evaluate `df` at a randomized
      parameter vector, compare against a central difference of that residual's
      own `f` (`rtol=1e-6`, `atol=1e-8`). A wrong analytic derivative does not
      crash — it converges slowly, to the wrong branch, or not at all — so this
      test is the only thing standing between the feature and a very expensive
      debugging session.
- [ ] `df` writes **only** inside its declared `params`: assert every other
      column of the Jacobian row is exactly zero.
- [ ] A residual registered without a `df` raises at construction, not at solve
      time.

### Verification
- [ ] `uv run pytest -q tests/test_sketch_v1_corpus.py` — green, unchanged
      coordinates to 1e-9. **This is FR3.**
- [ ] `uv run pytest -q tests/test_sketch_jacobian.py` — green.
- [ ] `uv run pytest -q tests/test_sketch_bench.py -s` — paste the table.
      Expect ≈ 0.35 / 0.78 ms warm-drag at n_seg 25 / 50 (a ~66× improvement
      at 50). **Quote the before and after in the changelog.**
- [ ] Fresh-interpreter assertion: `import agentcad.toolkit.sketch` →
      `"OCP" not in sys.modules`.
- [ ] `make test` — state the count.

## Slice 3 — diagnostics: rank, DOF, free entities, redundant vs conflicting

### Files
- `agentcad/toolkit/sketch.py`
- `agentcad/core/tools_sketch.py`
- `tests/test_sketch_diagnostics.py` — **new**
- `docs/changelog/NNNN-sketch-diagnostics.md`

### Tasks
- [ ] `rank` from `numpy.linalg.svd(J, compute_uv=False)` with tolerance
      `max(m,n)·σ₀·1e-10`; `dof = n_params − rank`. **Replace the shipped
      `dof = n_params − n_residuals`** — it reports a *negative* DOF for any
      redundant constraint (design Decision 6 has the six-sketch table).
- [ ] `free_entities` from the null space: for each right-singular vector
      beyond `rank`, map the parameter slots with non-negligible components back
      to their owning entity name. A bare `dof: 2` is not actionable; "2 DOF,
      free: p7, c3" is.
- [ ] **Dependent set by declaration-order greedy forward selection**:
      incremental modified Gram–Schmidt over residual rows *in spec order*; a
      row that does not raise the rank is dependent on rows declared earlier, so
      the blame lands on the later constraint. **Do not use column-pivoted QR** —
      measured to blame an innocent original constraint in 2 of 3 cases.
- [ ] Split the dependent set: a dependent row satisfied at the solution
      (`|f| ≤ 1e-7`) is **`redundant`**; violated is **`conflicting`**.
- [ ] `status ∈ {well_constrained, under_constrained, over_constrained,
      did_not_converge}` per design Decision 7.
- [ ] **`over_constrained` alone is not an error.** Redundant-but-consistent
      returns `ok: true` with the solved coordinates and `redundant: [...]`.
      Only a non-empty `conflicting` raises `ValidationError`, with the full
      `diagnostics` block in `details.diagnostics` (the PRD's agent path).
- [ ] FR5 time budget: **50 ms** on the greedy pass, checked against
      `time.monotonic` between rows. On exhaustion emit
      `analysis_complete: false` and **omit** `redundant`/`conflicting` — "we
      did not look" is never rendered as "nothing found" (the PRD-008
      `unverified` rule).
- [ ] Tool description states plainly that `conflicting` is *a* dependent set,
      not the unique culprit, and that declaration order is the heuristic.

### Tests (`tests/test_sketch_diagnostics.py`)
- [ ] The four-case rectangle table from design Decision 6 — redundant
      `parallel`, duplicate `distance=50`, contradictory `distance=60`,
      duplicate `horizontal` — each asserting the **added** constraint's index
      is the one named, and in the right set. **This is AC3.**
- [ ] Regression: assert that column-pivoted QR would have blamed a different
      constraint on the duplicate-distance case, so a future "simplification"
      back to pivoted QR fails loudly with an explanation.
- [ ] Under-constrained rectangle → `dof == 2`, `status ==
      "under_constrained"`, `free_entities` naming the two free corners.
      **AC4 (payload half).**
- [ ] Every over-constrained sketch from the table reports `dof == 0`, never a
      negative number.
- [ ] A redundant-but-consistent sketch returns `ok: true`; a contradictory one
      raises `ValidationError` carrying `details.diagnostics.conflicting`.
- [ ] The budget path: a synthetic 400-constraint sketch with the budget forced
      to 1 ms returns `analysis_complete: false` with the sets absent.

### Verification
- [ ] `uv run pytest -q tests/test_sketch_diagnostics.py` — green.
- [ ] Print the measured greedy cost at 50/100/200 residual rows; expect
      ≈ 1.8 / 6.4 / 25.8 ms. Record it — slice 8 depends on this being off the
      drag path.
- [ ] `make test` — state the count.

## Slice 5 — arcs, generalized tangency, and the new constraints

### Files
- `agentcad/toolkit/sketch.py`, `agentcad/core/tools_sketch.py`,
  `agentcad/server/routes_sketch.py`
- `tests/test_sketch_arcs.py` — **new**
- `docs/changelog/NNNN-sketch-arcs-and-constraints.md`

### Tasks
- [ ] `arc` entity: `(centre point, r, θ₁, θ₂)`, angles **degrees in the spec,
      radians internally**. Accept both the centre form and the 3-point form
      (the latter compiles to the centre form at ingestion and records which
      form was authored, for slice 7's emitter).
- [ ] **Virtual point handles**: `arc1.start` / `arc1.end` resolve through
      `PointRef` to derived coordinates and a chain-ruled gradient over
      `{cx, cy, r, θ}`. **No extra parameters and no extra residuals** — the
      rejected alternative (free endpoint points tied back by residuals) adds
      machinery the user never wrote to every conflict report (design
      Decision 3).
- [ ] Angles are **not wrapped mid-solve**. Unwrap continuously across frames
      and normalize on output only — wrapping a parameter is a Jacobian
      discontinuity and is how an arc jumps the long way round during a drag.
- [ ] `tangent {a, b, at?}` as **one constraint with a dispatch table** over
      `CurveRef` kinds: line–circle/line–arc (v1's residual, reused verbatim,
      including the 3-row `at` form), circle/arc–circle/arc (v1's
      `tangent_circles` residual, `kind: external|internal`).
- [ ] `symmetric {a, b, about}` — **2 rows**: the midpoint of `ab` on `about`
      *and* `ab ⟂ about`. The midpoint row alone looks right on a rectangle and
      is wrong on everything else.
- [ ] `equal_length {l1, l2}`; `concentric {a, b}` (2 rows, centre coincidence);
      `equal_radius` extended to arcs; `coincident` accepting virtual handles.
- [ ] **`tangent_line_circle` and `tangent_circles` stay registered for ever** —
      they are in the shipped tool description, `docs/part-authoring.md`,
      `docs/agent-api.md` and the v1 corpus. `tangent` is a new front door, not
      a rename.
- [ ] Whitelist `arcs` in the route; extend the tool schema.

### Tests (`tests/test_sketch_arcs.py`)
- [ ] `df` central-difference coverage for every new residual (slice 2's
      harness, extended — mechanical, non-negotiable).
- [ ] A tangent line–arc–line fillet run: solve, then assert the tangency
      analytically (centre-to-line distance == r, and the junction point is
      shared).
- [ ] Arc–arc external and internal tangency.
- [ ] A closed chain of lines and arcs joined by `coincident` on virtual
      handles: solves, `dof == 0`, and the junction coordinates agree to 1e-9.
- [ ] `symmetric` on a point pair and on a line pair about a construction line.
- [ ] `equal_length`, `concentric`, `equal_radius` on arcs.
- [ ] Arc parameter count: an arc adds exactly 3 parameters (+2 if its centre
      is a new free point), never 7.
- [ ] The v1 corpus still green (FR3).

### Verification

## Slice 6 — splines and slots

### ⚠ Spike first (feasibility unproven)
- [ ] **Spline fidelity spike.** The solver models a spline as its through
      points; build123d's `Spline` interpolates them with its own end
      conditions. Build the same point list through `Spline`, sample the real
      curve at parameter midpoints between consecutive points, and **measure**
      the maximum deviation from the solver's model for 5 representative
      control polygons (gentle, tight, S-curve, near-collinear, closed-ish).
      Write the numbers into the changelog.
      - deviation below the 1e-8 mm emission tolerance → proceed as designed;
      - above it → **fall back to `Bezier`** (control-point semantics, no
        interpolation), and document the semantics change in the same commit.
      Do not proceed on an assumption here — this is precisely the shape of the
      PRD-008 mistake.

### Files
- `agentcad/toolkit/sketch.py`, `agentcad/core/tools_sketch.py`,
  `agentcad/server/routes_sketch.py`
- `tests/test_sketch_splines.py`, `tests/test_sketch_slots.py` — **new**
- `docs/changelog/NNNN-sketch-splines-slots.md`

### Tasks
- [ ] `spline` entity: an ordered list of named `point` entities, degree fixed
      at 3, non-periodic. Its points are ordinary points, so **every existing
      point constraint works on them for free**.
- [ ] End tangency: `tangent {a: "sp1.start", b: "ln4"}` as a direction residual
      between the line and the first control-polygon leg. **On-curve point
      constraints are out of MVP** (PRD risk entry) — the tool description and
      the docs say so plainly rather than shipping something ambiguous.
- [ ] `slot {name, c1, c2, width}` **compiles at ingestion** into two arcs, two
      lines and their auto-constraints, with **one shared radius parameter** —
      so equal-radius is structural and can never appear in a conflict report.
- [ ] Every compiled residual carries the **slot's own `con_index`** plus
      `origin: "slot:<name>"`. **A diagnostic never blames a constraint the
      user did not write**; `details.origin` names `slot1.arc_a` for anyone who
      wants the sub-entity.
- [ ] Reserve the sub-entity namespace: a user entity named `slot1.arc_a` is a
      `validation_error` at ingestion, never a silent collision.

### Tests
- [ ] Spike results captured as a test with the measured tolerance asserted.
- [ ] `df` central-difference coverage for the new residuals.
- [ ] A slot solves; its two arcs share one radius; `dof` matches the hand
      count; the four junctions are tangent to 1e-9.
- [ ] A conflict inside a slot reports the **slot's** index, with
      `details.origin == "slot:<name>"`.
- [ ] A user entity colliding with a reserved sub-entity name raises.
- [ ] A spline with a fixed end tangent solves and the tangent holds.

      centre-parametrized arc chain at 6 decimals leaves a **7.58e-7 mm** gap
      and `make_face()` raises *"Face can only be created with closed wires"*;
      7 decimals (3.7e-8 mm) is the first that closes.
- [ ] **Prefer endpoint-anchored constructors** in a chain — `RadiusArc(start,
      end, r, short_sagitta=…)`, `ThreePointArc`, `TangentArc` — over
      `CenterArc`. Measured: endpoint-anchored closes at every precision tested
      because the arc and both neighbours are literally the same rounded pair.
- [ ] **The closure gate.** Before returning, compute the maximum
      vertex-to-vertex gap **from the formatted literals** and refuse to emit
      `make_face()` when it exceeds **1e-8 mm**, raising a `validation_error`
      that names the junction. Emitting code that will not rebuild is the one
      failure this feature must not produce.
- [ ] The mapping table of design Decision 10, including: **a slot inside a
      larger closed profile emits as its compiled primitives**, never as
      `SlotCenterToCenter` (which is a BuildSketch face at the origin, not a
      `BuildLine` curve).
- [ ] `emit` becomes an optional field on `solve_sketch` and a whitelisted key
      on the route, so the GUI and agents share one emitter.

## Slice 8 — the drag protocol on the solver and the route (AC2, solver half)

### Files

### Tasks
- [ ] `drag {point, x, y, weight?}` compiles to a **weighted soft residual
      block appended after the constraint rows**, default weight **0.05**
      relative to millimetre-scaled constraint rows (the measured value —
      record it as a named constant with the measurement beside it).
- [ ] **The drag residual is an objective, not a constraint.** Exclude it from
      `ok`, `max_residual`, `n_residuals`, the rank, the DOF and the
      diagnostics. Measured: including it makes every drag of a
      fully-constrained entity report `ok: false` with `max_residual` climbing
      to 2.43 over a 48 mm drag.
- [ ] **Diagnostics caching.** Cache the diagnostics block against a hash of
      the *compiled residual structure*; a drag frame changes no constraints, so
      it returns the cached block. `diagnostics: "auto" | "full" | "cached"`
      lets an agent force a recomputation. This is what turns a measured ~8 ms
      frame into ~1.5 ms.
- [ ] Whitelist `drag` and `diagnostics` in the route.
- [ ] **Change the route handler from `async def` to `def`**, so FastAPI runs
      it in the threadpool instead of on the event loop. Today's `async def`
      calls a synchronous solver directly on the loop; a long solve blocks the
      `/ws` event channel and every other request. One keyword.
- [ ] Extend the benchmark: a **scripted 100-step drag** of a cam lobe, warm-
      started from each previous frame, asserting p50 ≤ 16 ms and **zero
      branch flips** (sign of a chosen orientation invariant across the sweep).

### Tests (`tests/test_sketch_drag.py`)

- [ ] `n_residuals`, `rank` and `dof` are identical with and without a `drag`

- [ ] A drag frame with `diagnostics: "cached"` returns the same block as the

- [ ] Route test proving `drag` reaches the solver and that the handler is not

## Slice 10 — GUI: drag-to-solve, the DOF chip, conflict highlighting (AC2, AC4, AC7)

### ⚠ Spike first (feasibility unproven)
- [ ] **Browser drag latency spike.** Every HTTP number in the design was
      measured from Python httpx (0.72 ms p50 keep-alive; **12.55 ms p50 / 16.47
      ms p95 without**). Chrome's `fetch` has its own scheduling, and the
      sketcher shares a page with a Three.js renderer. In a real browser
      session against the real server: drive **200 synthetic drag frames**
      through the drag path, record end-to-end p50/p95/max from `pointermove`
      to re-render, and **confirm from the network panel that the connection
      was reused** (a fresh connection per frame eats 78% of the budget on its
      own).

      - p95 > 16 ms → adopt client-side prediction (render the dragged handle
        immediately, reconcile on the response) — **chosen with the number in
        hand, not pre-built**.

## Rollback / landing notes

- **Slices 1–4 are pure solver work behind an unchanged public shape.** If
  anything downstream misbehaves, the v1 corpus is the discriminator: green
  corpus + red elsewhere means the bug is in the new surface, not the rewrite.
- **Slice 2 is the load-bearing one.** Every interactive target depends on it.
  If its benchmark does not show a ≥ 20× improvement at 50 entities, stop —
  something is wrong with the Jacobian assembly (most likely a `df` writing
  outside its `params`, which the slice-2 test catches, or a Jacobian
  reallocated per call).
- **Slices 9–12 are additive UI/geometry surfaces** and can land in any order
  after 8, except that 12 wants 7's emitter.
- **If the slice-10 browser spike fails its budget**, the fallback (client-side
  prediction) is a change inside `sketcher.js` only — the server contract does
  not move. Do not pre-build it.
- **If the slice-6 spline spike fails**, `Bezier` is the fallback and the
  semantics change is documented in the same commit; it does not block slots,
  which can land first.
- **If the slice-11 tangency spike fails**, ellipses still ship without
  tangency. Phase 2 does not block Phase 3.
- Every slice ends with `make test` green and a staged
  `docs/changelog/NNNN-<slug>.md`. Commits end with the `Co-Authored-By`
  trailer. Do not commit manifest-reformatting churn or the venv.
